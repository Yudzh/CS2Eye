# Итерация 2 — парсинг демо и внутренний рейтинг игроков

## Что реализовано

Загруженные `.dem` разбираются `demoparser2 0.41.4`. Для каждого игрока и каждой карты сохраняются Steam ID, nickname, диагностическое название команды, сыгранные раунды, kills, deaths, assists, фактический урон по противникам, ADR, KAST и внутренний рейтинг карты.

Warmup и технические раунды исключаются. Team kills и team damage не учитываются. Spectator, GOTV и сущности вне игровых команд 2/3 отбрасываются. Новые глобальные игроки автоматически не создаются.

## KAST

Раунд входит в KAST игрока, если выполнено хотя бы одно условие: игрок сделал kill, assist, выжил или его смерть была разменяна союзником. В первой версии trade определяется как последующая в том же раунде смерть убийцы от союзника погибшего.

```text
kast_percent = kast_rounds / rounds_played × 100
adr = total_damage / rounds_played
```

## CS2Eye Internal Rating v1

CS2Eye Internal Rating v1 — собственная открытая deterministic-формула проекта. Она не является копией рейтинга BO3.gg или HLTV. Шкала 0–10 выбрана только для удобства визуального сравнения с Avg BO3.gg.

Для одной демки:

```text
raw_rating =
    0.35 × kills_per_round
  + 0.10 × assists_per_round
  + 0.20 × (1 - deaths_per_round)
  + 0.20 × (adr / 100)
  + 0.15 × (kast_percent / 100)

internal_rating = clamp(raw_rating × 10, 0.00, 10.00)
```

Коэффициенты и идентификатор версии находятся в одном модуле. В `demo_player_stats` хранится `internal_rating_version = v1`; агрегат игрока также помечается версией. Итоговый рейтинг игрока — среднее рейтингов карт, взвешенное по числу раундов. Учитываются только успешные parse run, связанные игроки, версия v1 и строки с положительным числом раундов. `bo3_rating` и `player_strength` не изменяются и не используют внутренний рейтинг.

## Связь игроков

Сначала ищется точное совпадение `players.steam_id`. Затем выполняется точное сравнение нормализованного nickname без учёта регистра и крайних пробелов. Автопривязка происходит только при одном совпадении; Steam ID записывается в найденного игрока. Неизвестные и неоднозначные игроки сохраняются с `player_id = null`.

## API

Парсинг турнира и года:

```bash
curl -X POST http://localhost:8000/api/v1/demos/parse \
  -H 'Content-Type: application/json' \
  -d '{"tournament_name":"IEM Cologne","year":2026,"replace_existing":false}'
```

Конкретная демка:

```bash
curl -X POST 'http://localhost:8000/api/v1/demos/10/parse?replace_existing=true'
```

Статистика игроков конкретной демки:

```bash
curl http://localhost:8000/api/v1/demos/10/player-stats
```

Успешные результаты пропускаются, если `replace_existing=false`. Failed и pending запускаются повторно. Ошибка одного файла не останавливает пакет. При неудачном повторном разборе предыдущий успешный набор статистики сохраняется.

## Ограничения

Парсинг выполняется синхронно в HTTP-запросе. Нет командного рейтинга, round-history API, CT/T, economy, utility, bomb, opening, clutch, позиционной аналитики, scheduler, очереди и ручной привязки игроков. Формула рейтинга является прозрачной первой версией и вынесена отдельно для будущей замены.
