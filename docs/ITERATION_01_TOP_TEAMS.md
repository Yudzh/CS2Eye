# Итерация 01 — BO3.gg top-30

## Пользовательский сценарий

Администратор проверяет доступность рейтинга BO3.gg, затем одной кнопкой
обновляет активную аналитическую выборку. В интерфейсе отображаются ровно
30 активных команд.

## Источник

Публичная страница `https://bo3.gg/teams/valve-rankings/world` загружает данные
из `https://api.bo3.gg/api/v2`. `Bo3Client` сначала получает список официальных
дат Valve, затем загружает рейтинг на последнюю из них.

Клиент поддерживает стандартные `HTTP_PROXY`, `HTTPS_PROXY` и `ALL_PROXY`.
Они нужны только если VPN сам не маршрутизирует трафик Docker-контейнера.

## Правила

- принимаются только 30 команд;
- места должны быть уникальными и образовывать диапазон `1..30`;
- BO3.gg ID и slug команд должны быть уникальны;
- все строки должны относиться к одной дате рейтинга;
- ответ должен быть помечен BO3.gg как официальный рейтинг Valve;
- при ошибке текущая активная выборка не меняется;
- команда, вышедшая из top-30, остаётся в БД, но получает
  `is_analytics_active = false`;
- подробные данные неактивных команд дальше обновляться не будут;
- каждый успешный запуск создаёт неизменяемые рейтинговые снимки;
- исходный ответ BO3.gg сохраняется в записи запуска для диагностики.

## Границы итерации

Список из пяти игроков сохраняется только в исходном рейтинговом снимке.
Отдельные сущности игроков, тренер, роли, обнаружение замен и подробная
статистика относятся к следующим итерациям.

## API

- `GET /api/v1/teams`;
- `GET /api/v1/admin/bo3/top-teams/probe`;
- `POST /api/v1/admin/bo3/top-teams/refresh`;
- `GET /api/v1/admin/bo3/top-teams/runs/latest`.
