# Итерация 7: агрегированная статистика команды по карте

## Источники и включение данных

Агрегаты строятся только из нормализованных таблиц `demo_map_results` и
`demo_team_side_stats`; `.dem` повторно не читается. В расчёт входят parse runs со
статусом `success`, у которых `metadata_status = complete`,
`round_data_status = complete`, известны карта, команда и победитель, а также есть
согласованная строка статистики сторон.

Исторический рейтинг соперника нормализован в `demo_team_opponent_context`: одна
строка на участвующую внутреннюю команду в демке. Player stats сохраняют прежние
поля для обратной совместимости, но rank-group агрегаты используют team-level
context.

## `team_map_aggregates`

Бизнес-ключ: `team_id + map_name + scope_key`. `scope_key` устраняет неоднозначность
SQL `NULL` в уникальном ограничении. Сохраняются scopes:

- `all`;
- `recent:5`, `recent:10`, `recent:20`;
- `rank:top_15`, `rank:top_16_30`, `rank:outside_top_30`, `rank:unknown`.

Дополнительно используется `rank:tier_2_3`: матчи с соперником, название которого
известно из демки, но команда отсутствует во внутреннем Top-40 справочнике. Scope
`unknown` зарезервирован для случаев, когда нельзя определить даже название
соперника.

Повторный расчёт атомарно заменяет полный набор scopes пары и удаляет строки, если
валидных исходных карт больше нет. Recent сортируется по `match_date DESC`, затем
по `demo_file_id DESC`; карта без даты остаётся в `all`, но не входит в recent.

## Формулы

Все winrate передаются в диапазоне 0–100 и равны `null` при нулевом знаменателе.
Round/CT/T totals суммируются из `demo_team_side_stats`. Overtime maps берутся из
`went_to_overtime`, overtime rounds — из side stats. Промежуточные проценты не
округляются.

`sample_size_score` линейно интерполируется между контрольными точками спецификации
и зависит только от числа карт. `freshness_score` определяется возрастом
`last_match_date`; дата `today` доступна как аргумент бизнес-функции для тестов.
Эти показатели не являются map strength и не используются для прогноза.

## Пересчёт и API

Точечный пересчёт запускается после parsing, reclassify opponent ranks, ручной
правки map result, пересчёта side stats и замены файла. Массовый endpoint:

```http
POST /api/v1/analysis/team-maps/recalculate
```

поддерживает фильтры `team_id` и `map_name`; каждая пара коммитится отдельно, поэтому
ошибка одной пары не останавливает остальные.

```http
GET /api/v1/analysis/teams/{team_id}/maps
GET /api/v1/analysis/teams/{team_id}/maps/{map_name}
```

Первый endpoint возвращает все карты и scopes. Второй дополнительно возвращает до
20 последних матчей со счётом, CT/T и историческим контекстом соперника. Команды
31–40 и неактивные команды поддерживаются наравне с активными.

## UI и ограничения

Страница команды показывает W–L, map/CT/T winrate, окна 5/10/20, Top 15 и Top
16–30, объём и свежесть. Доступны фильтры минимальной выборки/свежести и сортировки.
Малые и устаревшие выборки сопровождаются предупреждениями.

В итерации не рассчитываются map strength, преимущество, вероятность победы,
veto/BO3 или сравнение агрегатов двух команд.
