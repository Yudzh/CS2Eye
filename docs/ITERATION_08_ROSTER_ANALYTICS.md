# Итерация 08: аналитика составов

Roster — это конкретное множество из пяти связанных игроков одной команды. Его fingerprint строится как SHA-256 от отсортированных внутренних `player_id`; порядок, nickname, роли, IGL и тренер в идентичность не входят. Замена любого игрока создаёт другой roster.

## Текущий состав

`team_rosters` хранит источник, надёжность и известный период активности, а `team_roster_members` — снимки пяти участников. Единственный текущий roster указан одновременно флагом `is_current` и ссылкой `teams.current_roster_id`. BO3-импорт создаёт или находит roster только при наличии ровно пяти активных основных игроков и не включает тренеров и substitutes. Дата не угадывается: используется дата источника или `null` с `active_from_source=unknown`. Парсер демки никогда не меняет текущий roster.

## Фактический состав демки

После записи `demo_player_stats` игроки группируются по `demo_team_id` и дедуплицируются по стабильному `player_id`. Пять связанных игроков дают `complete`; меньше пяти — `partial`, больше пяти — `needs_review`. Nickname остаётся только диагностикой. Ссылка сохраняется в `demo_team_rosters`, максимум по одной строке на команду демки. Stand-in тем самым образует отдельный roster и не попадает в статистику официальной текущей пятёрки.

Для старых данных используется `POST /api/v1/demos/rebuild-roster-links` с фильтрами `demo_file_id`, `team_id` и `replace_existing`. Endpoint читает сохранённые player stats, не `.dem`; недостаток данных возвращается в warnings.

## Агрегаты и API

`team_map_aggregates` имеет уровни `organization` (`roster_id IS NULL`) и `roster` (`roster_id IS NOT NULL`). Оба используют одинаковые all, recent 5/10/20 и rank-group scopes, CT/T, overtime, размер выборки и свежесть. Organization сохраняет прежнюю семантику всех валидных карт; roster принимает только `complete` links с полными результатом, раундами и side stats. Старые roster aggregates не удаляются при смене текущего указателя.

- `GET /api/v1/teams/{id}/rosters/current` — текущая пятёрка и известная дата.
- `GET /api/v1/analysis/teams/{id}/maps?aggregation_level=organization|current_roster` — карты выбранного уровня; default остаётся organization.
- `GET /api/v1/analysis/teams/{id}/maps/{map}?aggregation_level=...` — конкретная карта и последние 20 карт выбранного уровня.
- `GET /api/v1/analysis/compare/teams/{a}/{b}/current-rosters` — H2H только тех демок, где одновременно совпали оба актуальных roster.

UI по умолчанию открывает текущий состав, явно показывает малую/пустую выборку и сохраняет историю организации отдельным режимом. Compare сохраняет прежнее сравнение силы и добавляет независимый блок очных карт текущих пятёрок.

## Ограничения

Исторические roster не выводятся из nickname или даты матча. Substitution с более чем пятью уникальными участниками требует проверки. Модель пока считает карты, а не BO3-серии; прогнозы, synergy, veto и автоматическая смена текущего состава по последней демке не реализованы.
