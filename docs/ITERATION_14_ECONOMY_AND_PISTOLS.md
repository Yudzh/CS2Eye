# Итерация 14 — экономика и пистолетные раунды

## Источник данных demoparser2

Используется `demoparser2 0.41.4`. Адаптер читает событие `round_freeze_end` и
запрашивает на его tick свойства игроков `team_num` и `current_equip_value`
(`m_unCurrentEquipmentValue`). Значения пяти игроков суммируются отдельно для T
и CT. Это стоимость фактического снаряжения в конце freeze time, то есть после
закупки и непосредственно перед боевой частью раунда. `round_start_equip_value`
не используется: оно описывает стоимость до новой закупки во freeze time.

Если событие, tick, сторона или equipment value отсутствуют, состояние стороны
равно `unknown`. Оно никогда не превращается в eco и не попадает в знаменатели
экономических метрик.

## Классификация экономики v1

Пороги централизованы в `cs2eye.analytics.economy.config` и являются прозрачной
экспертной базовой версией, которую нужно проверить на накопленных распределениях:

- `eco`: team equipment value не больше 6 000;
- `full_buy` T: не меньше 18 000;
- `full_buy` CT: не меньше 20 000;
- `force_buy`: достоверное значение между eco и соответствующим full-buy;
- `unknown`: значение или сторона отсутствуют/некорректны.

Порог CT выше из-за стоимости M4, наборов сапёра и типичного набора гранат.
Force-buy определяется общей стоимостью пятёрки, а не наличием отдельного Deagle.

## Пистолетные раунды

Пистолетные раунды определяются только после существующей нормализации gameplay
rounds. Warmup, technical/restart и некорректные строки сначала отбрасываются.
Первый пистолетный — `regulation_round_number=1`, второй — `13`, то есть первый
раунд после смены сторон в MR12. Раунды overtime имеют
`regulation_round_number=NULL` и пистолетными не считаются.

В `demo_rounds` сохраняются `is_pistol_round` и `pistol_round_number=1|2|NULL`,
equipment value и economy state обеих команд.

## Метрики demo

`demo_team_economy_stats` содержит одну строку на demo и команду. Повторный parse
сначала удаляет старые строки, поэтому дублей нет.

- pistol conversion: команда выиграла pistol и следующий нормализованный
  regulation round;
- post-pistol против force: тот же следующий раунд, когда соперник имел
  `force_buy`;
- камбэк второго раунда: команда проиграла pistol, но выиграла следующий раунд;
- anti-eco: соперник имел `eco`, а команда имела достоверный не-eco закуп;
- full-buy против full-buy: обе команды имели `full_buy`;
- force против full-buy: команда имела `force_buy`, соперник — `full_buy`.

Eco, force-buy и full-buy win rate относятся к собственному состоянию команды.
Anti-eco хранится отдельно и с eco win rate не смешивается. Проценты не хранятся
в таблице: API вычисляет их из wins/opportunities и возвращает `NULL` при нулевой
выборке.

## Сохранения оружия

Надёжный save сейчас не реализован. Живой игрок в проигранном раунде сам по себе
не доказывает save, а текущий адаптер не связывает индивидуальный inventory в
конце раунда с inventory следующего freeze time. Поля `save_rounds` и
`players_saved` подготовлены, но равны нулю только вместе с явным
`save_data_status=not_parsed`; UI не показывает их как реальный нулевой результат.

## Статусы и качество данных

`economy_data_status`: `not_parsed`, `complete`, `partial`, `needs_review` или
`invalid`. Старые demo после миграции получают `not_parsed`. Полная экономика
требует complete round data и хотя бы часть достоверно классифицированных
gameplay rounds. Отдельные `unknown` допустимы и исключаются из знаменателей.
Это важно для split-demo: запись части может начинаться после `round_freeze_end`,
поэтому первый раунд такой части невозможно восстановить без догадки. Если
equipment value отсутствует у всех раундов, статус равен `partial`.

В Team Map aggregates экономика попадает только через строку demo со статусом
`complete`. Используются существующие scopes: all, recent 5/10/20, Top 1–15,
Top 16–30, tier 2–3, а также существующая фильтрация organization/current roster.
Новая система scopes или определения состава не создавалась.

## API и интерфейс

- `GET /api/v1/demos/{id}/economy-stats` — показатели конкретной demo;
- round API показывает pistol, equipment value и economy state обеих команд;
- Team Maps возвращает `economy` внутри каждого существующего scope;
- сравнение карт возвращает economy обеих команд.

Demo UI показывает pistol, conversion, eco, force, full buy, anti-eco, full-vs-full
и камбэк. Team Maps показывает основные показатели и расширенные детали по всем
scope. Team Compare показывает краткое сравнение экономики для каждой карты.

## Миграция и повторный парсинг

Миграция `0018_economy_and_pistols` не удаляет demo и выставляет старым картам
`not_parsed`. Для наполнения данных нужен существующий повторный парсинг с
`replace_existing=true`: кнопка «Повторить парсинг», массовые кнопки страницы demo
или существующий parse API. После parse затронутые organization/current-roster
агрегаты пересчитываются тем же механизмом, что CT/T и bomb analytics.

## Ограничения

Пороговая версия не учитывает состав конкретного inventory, потерянное оружие во
freeze time и распределение закупки между игроками. Она не входит в Player,
Team или Map Strength. `economy_score` и `pistol_score` не вычисляются до анализа
реальных распределений. Predictive model в этой итерации отсутствует.
