# Правила развития CS2Eye

## Главный принцип

В работе одновременно находится только один продуктовый слой. Следующий слой
не начинается, пока текущий не соответствует своему Definition of Done.

## Что считается одним слоем

Слой — это один законченный пользовательский сценарий, а не набор разрозненных
backend-задач. Если сценарий виден пользователю, в него одновременно входят:

1. модель данных и миграция;
2. бизнес-правила;
3. API;
4. UI;
5. автоматические тесты;
6. проверка запуска в Docker;
7. краткое обновление документации.

## Definition of Done

Функция готова, только если:

- сценарий сформулирован одним предложением;
- определены входные данные и ожидаемый результат;
- учтены пустые, ошибочные и пограничные состояния;
- миграция применяется на чистой БД;
- API имеет стабильный контракт;
- UI поддерживает основной сценарий и показывает ошибки;
- backend-тесты проходят;
- frontend собирается без ошибок;
- весь compose-проект поднимается одной командой;
- незавершённых заглушек этого слоя не осталось.

## Порядок работы над слоем

1. Описать один пользовательский сценарий.
2. Зафиксировать минимальные поля и бизнес-правила.
3. Согласовать API-контракт и состояния UI.
4. Реализовать вертикальный срез от БД до интерфейса.
5. Проверить Definition of Done.
6. Только после этого выбрать следующий слой.

## Что нельзя добавлять «на будущее»

- таблицы без текущего сценария;
- endpoints без UI или непосредственного потребителя;
- UI-вкладки без работающего backend;
- универсальные абстракции без второго реального применения;
- фоновые задачи, кэш и интеграции до появления подтверждённой необходимости;
- расчётные поля, которые пока нигде не используются.

Старый проект и его код остаются отдельным черновиком и источником решений.
Код переносится из него по частям только после проверки, что он нужен
текущему слою.
