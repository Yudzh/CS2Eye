# Итерация 11 — матчи и серии BO1/BO3/BO5

## Модель

`Tournament` нормализует название и год турнира, tier, LAN/online/unknown и период. Исходные `DemoFile.tournament_name` и `tournament_slug` сохранены для обратной совместимости.

`Match` хранит пару команд, дату, формат, этап, среду, playoff/elimination-флаги, счёт по картам, победителя и статус разрешения. Существующая `DemoFile` остаётся картой и получает только `match_id` и `map_number`; дублирующая таблица карт не создаётся.

## Автоматическое определение

После успешного парсинга сервис рассматривает только карты одной пары команд, одного строкового турнира и одной даты. Порядок сторон в `DemoMapResult` нормализуется.

Автоматическое `resolved` допускается при сильном сигнале:

- одиночный файл явно содержит `bo1`;
- все файлы имеют уникальные последовательные маркеры `map1…map5` или `m1…m5`.

Несколько подходящих карт без надёжного порядка создают предполагаемую серию `needs_review`; она видна администратору, но не участвует в статистике серий. Одиночная неопределённая карта получает `unresolved`. Разные даты и турниры не объединяются. В сохранённых metadata нет времени начала, поэтому близость времени не угадывается.

## Ручное управление и результат

API и UI позволяют создать серию из demo ID, подтвердить предложение, разделить карты и изменить их порядок, формат, этап, среду и флаги. Только `resolved` пересчитывает результат. Стороны каждой карты приводятся к `Match.team_a/team_b`; победы по картам дают счёт серии и `winner_team_id`. Формат задаёт порог завершения: BO1 — 1, BO3 — 2, BO5 — 3 победы.

## Статистика

Командная статистика использует только `resolved` и `completed` серии. Возвращаются total/W/L/winrate, BO1/BO3/BO5 и LAN/online/playoff/elimination/final.

В режиме `current_roster` текущий roster команды должен иметь `DemoTeamRoster(resolution_status=complete)` на каждой карте серии. Серия со сменой состава исключается целиком.

H2H продолжает считать прежний рейтинг исключительно по картам, но дополнительно показывает победы в надёжно определённых сериях. Для current-roster H2H точные текущие roster обеих команд должны совпасть на всех картах серии.

## API

- `GET /api/v1/matches`
- `GET /api/v1/matches/{id}`
- `POST /api/v1/matches`
- `PATCH /api/v1/matches/{id}`
- `POST /api/v1/matches/{id}/reorder`
- `POST /api/v1/matches/{id}/split`
- `GET /api/v1/analysis/teams/{id}/matches?aggregation_level=organization|current_roster`

## Ограничения

Нет veto, pick/ban, прогнозов, betting, odds, economy, utility, LLM и scheduler. Этап и формат не выводятся из внешнего источника. Сомнительные серии требуют ручного решения и до него не влияют на match/H2H-series статистику.
