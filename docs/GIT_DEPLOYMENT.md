# Ручной деплой из Git

Сервер: `82.146.63.83`. Репозиторий: `Yudzh/CS2Eye`.
Production-ветка — **`telegtam-prod`** (имя сохранено как в репозитории).
Обновления запускаются вручную; GitHub Actions только проверяет тесты и сборку UI.
GitHub Secrets и доступ VPS к GHCR не нужны. Репозиторий публичный, сервер читает
его по HTTPS без ключа GitHub.

## Обычное обновление

На компьютере закоммитить нужные изменения и отправить production-ветку:

```bash
git switch telegtam-prod
git add <нужные-файлы>
git commit -m "Описание изменения"
git push origin telegtam-prod
```

На сервере:

```bash
cs2eye-deploy
```

Либо одной командой с этого компьютера:

```bash
ssh -i ~/.ssh/cs2eye_vps root@82.146.63.83 cs2eye-deploy
```

Команда берёт последний коммит ветки, создаёт отдельный каталог релиза,
собирает Docker-образы с тегом полного SHA до остановки приложения,
проверяет PostgreSQL и делает `pg_dump -Fc` с проверкой оглавления дампа.
Затем останавливает API и бота, применяет миграции и обновляет API, бота и UI.
Проверяет readiness API и запрос пароля сайта (HTTP 401).
Сборка на VPS занимает несколько минут; короткий перерыв начинается после сборки.
Если сборка или бэкап не удались, работающие контейнеры не останавливаются.

Команда не запускает pytest на VPS: перед деплоем проверить успешный CI
для выбранного коммита. Незакоммиченные файлы компьютера на сервер не попадают.

## Каталоги и данные

- `/opt/cs2eye/repository.git` — локальный Git-кеш production-ветки;
- `/opt/cs2eye/releases/<SHA>.<суффикс>` — исходники отдельных попыток деплоя;
- `/opt/cs2eye/current` — последний успешно проверенный релиз;
- `/opt/cs2eye/previous` — предыдущий успешно проверенный релиз;
- `/opt/cs2eye/shared/.env.prod` — актуальные production-секреты;
- `/opt/cs2eye/shared/secrets/web.htpasswd` — хеш пароля сайта;
- `/opt/cs2eye/shared/deploy.conf` — URL Git и production-ветка;
- `/opt/cs2eye/shared/use-bo3-proxy` — подключает существующий AdGuard-прокси;
- `/opt/cs2eye/shared/use-https` — только для HTTPS-профиля Docker Compose;
- `/opt/cs2eye/backups` — дампы БД перед обновлениями.

Compose сохраняет имя проекта `cs2eye-prod`, тома `cs2eye-prod_pg_data` и
`cs2eye-prod_demo_storage`. Контейнер БД при обновлении приложения не пересоздаётся.
Исходная установка в `/opt/cs2eye` сохраняется. После перехода на новую схему
редактировать секреты нужно в `shared`, а запускать обновления — `cs2eye-deploy`.
Внешний Nginx и существующая конфигурация доступа остаются на хосте.

Для журналов и состояния использовать каталог релиза и те же Compose-файлы:

```bash
cd /opt/cs2eye/current
export CS2EYE_RELEASE=$(basename "$(readlink -f /opt/cs2eye/current)" | cut -d. -f1)
export CS2EYE_IMAGE_PREFIX=cs2eye
docker compose --env-file /opt/cs2eye/shared/.env.prod -f compose.prod.yml -f compose.bo3-proxy.yml -f compose.release.yml ps
```

Для логов добавить `logs --tail 100 api bot webui` вместо `ps`.
Если прокси не используется, убрать `-f compose.bo3-proxy.yml`.
Не выполнять `down -v`: эта команда удаляет данные.

## Неудачный релиз и возврат версии

Если миграция или запуск не удались, команда завершится с ошибкой и напечатает
каталог неудачной попытки. `current` останется на последнем успешном релизе,
но API/бот после неудачной миграции или запуска могут быть остановлены.
Автоматического отката схемы нет. Для диагностики перейти в каталог неудачной
попытки и посмотреть логи с её SHA и теми же Compose overrides.

Повторный деплой или возврат к коммиту из истории production-ветки:

```bash
cs2eye-deploy <полный-40-символьный-SHA>
```

Перед возвратом проверить совместимость старого кода с текущей схемой БД.
Дамп не восстанавливать поверх рабочей БД без отдельного плана восстановления.
Релизы, образы и дампы автоматически не удаляются; контролировать место.
Копии на том же VPS не защищают от потери сервера — скачивать их отдельно.

## Подготовка существующего сервера

Из checkout с новыми файлами деплоя, от root:

```bash
bash deploy/bootstrap.sh
cs2eye-deploy
```

Bootstrap проверяет существующую production-БД, копирует секреты в `shared`
только если их там ещё нет, определяет использование прокси и устанавливает
`/usr/local/bin/cs2eye-deploy`. Контейнеры при подготовке не перезапускаются.
Повторный bootstrap сохраняет актуальные shared-секреты. После изменения
`deploy/update.sh` повторить bootstrap из актуального checkout для обновления
установленной команды. Сам `deploy/release.sh` всегда берётся из выбранного коммита.
