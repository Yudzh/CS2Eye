# Основные сведения о командах из PandaScore

В карточке существующей команды доступен поиск по названию через бесплатный
`GET /csgo/teams?search[name]=...`. Администратор сверяет название, страну,
логотип, slug и ID, затем выбирает запись. Автоматического сопоставления по
названию нет: реальный поиск Aurora возвращает несколько разных команд.

После выбора сохраняются PandaScore ID, slug, снимок профиля и время получения.
Название, логотип и код страны обновляются из профиля. Отсутствующий логотип или
страна не стирают существующие значения. Название страны очищается при изменении
кода, чтобы не показывать страну от предыдущего профиля. Дальнейшее обновление
получает профиль по сохранённому ID. Один PandaScore ID нельзя назначить двум
командам; повторная привязка уже связанной команды к другому ID запрещена.

Внутренние и BO3 ID, составы, рейтинги, прогнозы и результаты сохраняются.
Импорт рейтинга и команды из BO3 продолжает работать, но не перезаписывает
название, логотип и страну после сохранения профиля PandaScore.
Запросы команд используют общий часовой бюджет и блокировку синхронизации
результатов. Токен остаётся на сервере.

## Доставка

Миграция `0064_pandascore_teams` добавляет поля и уникальный индекс. Обязательных
заранее созданных данных для этой функции нет; профили сохраняются через UI в
серверной БД. Публикация выполняется штатным `cs2eye-deploy` из `telegtam-prod`.
На VPS необходимо настроить `PANDASCORE_API_TOKEN` для API.

После доставки проверить через веб-панель поиск, выбор профиля, сохранение после
перезагрузки и повторное обновление по ID; сверить ответ API и неизменность
рейтинга и состава. До этих проверок функция не считается проверенной на VPS.

## Основной и турнирный составы

Миграция `0065_pandascore_rosters` добавляет PandaScore ID игроков, сохранённый
список основного состава и привязку стадии турнира. BO3 ID игрока может быть
пустым: новым игрокам PandaScore не назначаются вымышленные BO3 ID. Существующие
игроки сопоставляются сначала по PandaScore ID, затем по единственному точному
нику без учёта регистра и совместимой стране. Неоднозначное сопоставление
отклоняется; Steam ID, рейтинги и история существующего игрока сохраняются.

В карточке команды кнопка получения состава сохраняет общий список PandaScore.
Ровно пять игроков становятся основой. Для шести и более требуется выбор пяти
в веб-панели; неполный список не меняет предыдущую основу. Остальным игрокам не
назначается автоматически роль запасного или тренера. Импорт BO3 больше не
перезаписывает принятую основу и её активные членства; рейтинг Valve обновляется.
Обновление связанных команд работает в API: проверка каждые 15 минут, загрузка
общего списка не чаще раза в шесть часов. Изменение основы получает дату
наблюдения, не выдаётся за известный ранее состав.

В разделе составов турнира можно проверить и выбрать ID стадии PandaScore.
Если у привязанных матчей уже есть единственный общий ID стадии, он используется
автоматически. Состав берётся из `/tournaments/{id}/rosters`, команда выбирается
по сохранённому PandaScore ID. Допускается только пять уникальных игроков.
Турнирная пятёрка не меняет основную и не создаёт автоматически фактор временной
замены. Ручные замены остаются в приоритете. Успешный турнирный снимок фиксируется
с текущим временем получения и повторно автоматически не перезаписывается.
Фоновый процесс запрашивает такие составы для текущих турниров; вручную можно
получить состав заранее. Без нужных привязок проверка выдаёт явную ошибку.

`cs2eye.deployment.prepare` проверяет целостность сохранённых основных и
турнирных привязок перед проверкой прогнозов. Готовые прогнозы не пересчитываются
и не получают новые даты. Откат миграции запрещён при наличии игроков без BO3 ID,
чтобы не потерять их связи и историю.

Реальный бесплатный API дополнительно проверен через сервис импорта на отдельной
SQLite БД в памяти: Aurora Gaming — общий список из шести игроков требует выбора;
турнирный список PGL (22222) содержит пять; явный выбор основной пятёрки сохраняется.
Production-БД этой проверкой не изменялась.
